# Codebase Map — BOQ / Building Editor (`boq`)

> Auto-generated by Cartographer. Last mapped: 2026-07-02 (ERP sync layer; rest 2026-06-27).
> Vite + React 19 + Zustand 5 SPA for architectural + MEP design documentation in Indian
> residential construction. It is the upstream **Building Editor** that feeds the JRM ERP
> (`erp-saas`) via a stable `ifcGlobalId` contract and live per-mutation geometry sync.
> Deploys to Cloudflare Workers. No backend of its own; IDB-first persistence.

**Five-layer architecture (data flows DOWN; mutations only at the top):**
`Geometry (Zustand store) → Topology (pure) → Quantities (pure) → BOQ Presentation → UI + Export`.
Topology and quantities are pure functions of state — no side effects. The editor is the
**single source of truth**: it writes a **canonical Building Document to R2** (authoritative) and the
ERP's PostgreSQL is a disposable projection written live via `/geometry/*`. On reopen the canvas is
loaded **verbatim from the canonical document — never reconstructed from the projection** (that path
was deleted 2026-06-30).

## State Core (`store.js`, slices, `operations/`)

A single **Zustand 5** store (`useStore`) holds every entity collection as `{ [internalId]: entity }` plus UI/view state and undo/redo history — all flat at the root (the namespaced model/view/history/validation/cache split is documented in `store/legacyAccessors.js` but **not yet implemented**). Every entity has an internal `id` (UUID, runtime) AND an `ifcGlobalId` (22-char base64, stable, the ERP + future IFC key). Structural mutators call `_save()` (snapshots 17 collections into a 50-frame ring buffer; view state excluded) and bump `boqRevision`. `_runAtomically(fn)` collapses a batch into one history frame (`_inBatch` suppresses nested `_save`). The `operations/` journal/dispatch pipeline exists fully but is **dormant** — the live store uses direct `set()`.

| `structuralSlice.js` | `addColumn/addBeam/addBeamWithEndpoints/addSlab/addFoundation`, `setProjectSettings`, `addFloor`; exports `DEFAULT_PROJECT_SETTINGS`, `DEFAULT_FLOOR_ID='F1'` |

**Entity shapes:** `Node{id,ifcGlobalId,x,y(in),floorIds,kind:CORNER|TJUNCTION,onWallId}` · `Wall{id,ifc,n1,n2(node ids),height,thickness,materialKey,openings[],floorId,junctions[],...}` · `Room{id,ifc,name,wallIds[],nodeOrder[],type,finishes,floorId}` · `Column{id,ifc,x,y,columnTypeId,baseFloorId,topFloorId}` · `Beam{id,ifc,endpoints:{from,to} 4-type union,level,source}` · `Slab{id,ifc,type,roomIds,thicknessIn,grade}` · MEP `baseEntity{id,ifc,discipline,type,x,y,wallId,roomId,...}`.

**Locked rules:** centerline storage is canonical (draw-mode converts at authoring boundary only); walls are **never split** (T-junctions are graph nodes in `wall.junctions[]`); `ifcGlobalId` is generated once, never changed; beam endpoints resolve through `resolveBeamEndpoint()` (4-type union); `DEFAULT_FLOOR_ID='F1'`; history is entity-only.

## Persistence, ERP Sync & Export (`src/projects`, `src/export`)

Two-tier persistence. **Standalone:** IDB-first — `manager.js` (sync read cache + async IDB writes + BroadcastChannel cross-tab + localStorage migration) and `autosave.js` (30s debounced, **LOCAL IDB ONLY, never cloud**).

**ERP-launch mode — Canonical Building Document (migration COMPLETE 2026-06-30).** The editor writes a **canonical JSON snapshot (`buildSnapshot`, schemaVersion 7) to R2 as the single source of truth**; on reopen the canvas is loaded **verbatim from that document — reconstruction from the PostgreSQL projection was DELETED** (`erpReconstruct.js` and `hydrateFromErp`/`reconstructSnapshot` no longer exist). Boot (`main.jsx` → `erpSession.initErpSession`): `parseErpLaunchHash` parses+strips the `#erpLaunch?buildingId=&token=&erpUrl=` fragment → `_buildFloorIdsMap` (creates F1 if new) → `initLiveSync` → `initLiveSyncQueue` → `reopenCanvas` (canonical R2→IDB→empty) → `initCanonicalSyncQueue` → `startSyncEngine({coordinated:true})` → `startSyncCoordinator`.

**The write pipeline is a strict ACCEPT→EMIT ordering owned by `syncCoordinator`** (one microtask-coalesced tick per committed store change, gated on `_inBatch`):
1. **ACCEPT** — `buildSnapshotDoc(state)` → durably `put` to IDB `snapshots` store → `noteCanonicalDirty()` + debounced (`10s`) `pumpCanonicalUpload` to R2 via `canonicalSyncQueue`.
2. **EMIT** — *only after ACCEPT resolves* — `flushSyncEngine(st)` diffs vs a shadow snapshot and enqueues ordered ops into the durable IDB-backed FIFO outbox (`liveSyncQueue`) that drains sequentially through `liveSync.fireLiveOp` (exp-backoff, 4xx → dead-letter) as `/geometry/*` REST calls. If ACCEPT throws, EMIT is withheld (Invariant #5: accept-before-project).

`syncEngine` runs in `coordinated:true` mode in production — it does **not** self-subscribe; `flushSyncEngine` is the only entry point, called exclusively by the coordinator.

**Floor-identity safeguards** (the default floor reuses the constant `sourceEditorId='F1'`, `DEFAULT_FLOOR_ID` in `structuralSlice.js`, across *every* building; ERP floor identity is therefore building-scoped): (1) `initLiveSync()` **clears `_idMap` on every launch** (a module-scoped map otherwise leaks another building's floor/room ids → backend 403); (2) `ADD_ROOM` resolves its floor **only** from this connection's `floorIds` (`_ensureFloorErpId`), never the global `_idMap`, and creates the floor under the current building if missing; (3) `SAVE_ROOM_VERTICES` **no-ops on an unresolved room id** (never POSTs `/rooms/null/vertices`).

**Locked rules:** autosave is LOCAL-only; **reconstruction is removed** — canonical is never derived from the projection; ACCEPT before EMIT (#5); one canonical + one projection lineage per mutation (#7); `sourceEditorId == ifcGlobalId == internal id` identity so wall→node refs + id-map resolve for UPDATE not duplicate ADD; coordinate mapping lives ONLY in `syncMappers`/`elementRegistry`; enum mappers are total (never throw — fall back to OTHER/INTERNAL/WINDOW); queue is strictly FIFO-sequential (parent-before-child ordering); **a new element kind = ONE entry in `elementRegistry.js`** (syncEngine/syncEmitters are registry-driven); `roomTypeCode` intentionally omitted from `roomAddOp` (ERP defaults to OTHER).

**Quality gate (6 verify scripts, gate every geometry change):** `verify-canonical-sync` (byte-for-byte topology preservation through the R2 round-trip + stale-base→409) · `verify-canonical-reopen` (R2→IDB→empty load, no reconstruction) · `verify-invariant-5-7` (accept-before-emit + one lineage each) · `verify-floor-sync` (mid-session floor create: one ADD_FLOOR before ADD_ROOM, real floorErpId) · `verify-floor-delete` (DELETE_FLOOR after child deletes, FK-safe) · `verify-live-sync` (per-op HTTP contract over `GEOMETRY_OPS`). **Caveat:** `package.json` has NO `verify` script wired — these run as standalone `node scripts/verify-*.mjs` despite CLAUDE.md's `npm run verify` claim.
